# Starting with the user's questions

The main questions are: **Can I still return this? What needs checking? What
expires next? How do I start a claim? Where is my receipt?**

The overview offers confirmed dates and a separate attention list. Unknown
policy information is a visible task, not a guessed return window. Details show
the applicable terms/source, calculation and exact missing input. A confirmed
date is not a guarantee of eligibility; exceptions remain visible for review.

Receipt upload leads directly to editable suggestions with field evidence.
Purchase details and policy verification have separate controls because seeing
a date on an invoice is not the same as establishing which policy applies.
Manual entry requires only a product description; people can save an incomplete
record and return later to add terms.

Requests use confirmed purchase details and remain editable. Copy/download let
the user send through their usual channel. Marking a record refunded is clearly
a local status update, without implying a bank/merchant confirmed it.

The interface uses a warm neutral background, restrained teal, readable status
labels/icons, a consistent sidebar, responsive layouts, keyboard focus and light/
dark themes. No external fonts/images load. Demo mode must be explicitly enabled
and remains labelled everywhere it appears.

Settings explains when reminders can run, what backups contain and what deletion
does. The user retains control of their data and exports. There is no silent
invoice transmission or automatic message sending.
